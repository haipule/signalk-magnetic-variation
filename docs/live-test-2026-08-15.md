# Live test record — 2026-08-15

## Scope

First installation test of `signalk-magnetic-variation` on a running Signal K
2.31.0 vessel server with multiple GPS sources.

## Input situation

The available NMEA 0183 inputs did not provide a usable variation:

- one Android RMC source explicitly sent the placeholder `0.0,E`;
- the Furuno/AIS RMC source left both variation fields empty;
- an AvNav Android test source also left both variation fields empty.

Exact device addresses, coordinates, serial identifiers, and backup paths are
intentionally omitted from this public test record.

## Installation and safety

Before installation, the Signal K service, socket activation, health-check
timer, and health-check service were all stopped and verified inactive. The
existing Signal K package configuration, plugin configuration, and source
priorities were backed up locally on the target. All services were restored
after installation.

## Result

The plugin calculated a westerly variation of approximately 15.88 degrees and
published it in Signal K radians:

```text
navigation.magneticVariation = -0.27715828521669955 rad
$source = signalk-magnetic-variation.XX
```

A path-specific priority override was added for
`navigation.magneticVariation` only. It prefers the plugin source and retains
the existing Android and AIS sources as fallbacks. No other navigation, GPS,
or wind priority was changed.

Three observations across more than 20 seconds showed the WMM source remaining
preferred with timestamps advancing at the configured ten-second publication
interval. Final service validation showed one Signal K server process, active
Signal K service and socket, an active health timer, and an inactive completed
health-check oneshot service.

## Conclusion

Pass. The plugin supplies a stable, independently calculated variation and
overrides the placeholder Android value without changing position-source
selection. Downstream magnetic-course output still requires a separate
instrument test.
